Quarterly Access Review Worksheet

Scope a review small enough to finish, run it the same way each quarter, and leave a record an examiner can follow.

Version 1.0 · Last updated November 5, 2026

Review details

Reviews fail when they try to cover everything at once. Pick one system per quarter (rotate through the high-risk ones first: email, core banking/ERP, finance, admin consoles) rather than attempting the whole environment.

Scope for this quarter

  • Chosen system is on the rotation and the right owner is assigned.
  • Current user and permission list exported from the system itself (not an old copy).
  • Privileged / admin accounts flagged for closer scrutiny.

User-by-user review

For each account, confirm the person still needs the access at the level granted. Mark the action and who approved it.

User / account Access level Still needed? (Keep / Reduce / Remove) Action taken & date Approved by

Red flags to confirm

  • No active accounts for people who have left (cross-check against offboarding records).
  • No shared or generic logins that can't be tied to a person.
  • No one carrying admin rights they no longer use.
  • No dormant accounts (no login in 90+ days) left enabled.

Close-out & evidence

  • All "Reduce / Remove" actions completed and dated.
  • Owner has signed off on the final access list.
  • Completed worksheet filed in the exam / evidence folder with the source export.

Based on the article Quarterly Access Reviews: Keep Them Small Enough to Finish.
